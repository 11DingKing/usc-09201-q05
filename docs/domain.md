# 森林经营方案年历领域约定

## 业务背景

“一次编制、多年管用”的经营方案铺开后，企业年度采收、补植、管护计划不能再各自
用表格维护。系统面向集体林权改革与林下产业协作场景，把多年目标拆为有前置关系的
年度任务，关联责任主体、适用地块、生态限制与批准版本。

## 不可变与追加原则

* 所有业务变更都是**追加事件**：方案版本、任务、禁作限制、延期申请与审批结论、
  拆分、回执、责任人交接、提醒发送均不删除、不覆盖。
* 跨年度延期批准后，任务同时保留“原计划窗口”（永久的逾期依据）和“有效窗口”；
  待决或被驳回的申请不改变任何窗口。
* 拆分后原任务保留原计划与已发生回执，子任务承担剩余工作量；时点在拆分之前仍显示
  原任务，之后显示子任务。
* 回执以业务编号去重且禁止超量；责任人交接保留完整任职链。
* 禁作/限制（政策边界、灾害风险、生态限制）是独立记录，只能新增或“提前解除”，
  绝不直接修改任务；任务在命中动作、地块、日期范围时显示暂停。

## 版本与时点

* 读模型（可执行清单、逾期依据、完成量、当前责任人、适用版本、提醒状态）一律是
  事件状态相对于某个 `as_of` 日期/时刻的纯函数，可任意模拟历史与未来时点。
* 换版只追加已批准版本；清单仅含当前版本任务和经批准延期跨入的 `carry_over`
  结转任务，历史版本的原始计划通过历史视图完整查阅。
* 服务重启后重放事件日志恢复全部状态；提醒触发时刻由有效窗口派生、发送状态持久化，
  待决审批不丢失、不漂移。

## 访问与追溯

涉及个人、机构或敏感地点的信息只应向职责范围内的角色开放，所有对外结果都应能够
追溯到所采用的方案批准版本与事实事件（事件序号 seq）。
